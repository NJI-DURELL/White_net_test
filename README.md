# Pulse — Network Speed Test

A fast, honest network speed test in the spirit of fast.com — download, upload, ping, jitter, streaming readiness and connection strength, measured live with smooth animated visuals. Built with Next.js on a fully serverless (Edge Function) backend.

**Live:** _fill in after deploy_

---

## Features

- Download & upload speed, shown in **MB/s** by default with a one-tap **Mbps** toggle
- Ping (latency) + jitter measurement, plus an estimated packet-loss rate
- **Network Strength** meter (Excellent → Very Weak) — a synthesized connection-quality score combining speed, latency, jitter and loss
- **Streaming readiness** rating (e.g. "Great for 4K", "Good for 1080p") based on sustained throughput
- ISP / connection panel — your public IP, ISP name, city/region, and the resolved test-server region
- Device info card (browser, OS, connection type where supported)
- Local test history with a trend sparkline (stored in your browser, never sent anywhere)
- Downloadable / shareable result card image
- Dark & light themes, fully responsive, reduced-motion aware

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | Next.js (App Router) + TypeScript |
| Styling | Tailwind CSS, hand-rolled glassmorphism design system |
| Animation | Framer Motion (springs for the live counter/gauge, choreographed phase transitions) |
| Backend | Next.js Route Handlers running on the **Vercel Edge Runtime** — no server process, no database |
| Charts/Gauge | Hand-rolled SVG (no chart library) for frame-accurate real-time smoothing |
| Geolocation | Vercel edge geo headers + free/keyless `ip-api.com` lookup |

- Node.js 18+
- npm 9+

### Install & Run

```bash
cd White_net_test
npm install
npm run dev
# Runs on http://localhost:3000
```

### Production build (matches Vercel Edge behavior more closely than dev mode)

```bash
npm run build
npm run start
```

## Environment Variables

None required. `ip-api.com` geolocation is free and keyless. In production on Vercel, `VERCEL_REGION` and the `x-vercel-ip-*` geo headers are populated automatically — they're blank when running locally with `next dev`.

## Deployment (Vercel)

1. Push this repo to GitHub (or connect it directly).
2. Import the project on [vercel.com](https://vercel.com).
3. Set **Root Directory** to `White_net_test`.
4. Framework preset: **Next.js** (auto-detected). No build command changes needed.
5. Deploy — the API routes deploy automatically as Edge Functions.

## How It Works / Notes

- **Download test:** an Edge Function streams randomly generated bytes for a fixed duration; the browser reads the response stream and measures real bytes-received-per-second in a rolling window.
- **Upload test:** the browser sends a randomly generated payload via `XMLHttpRequest` (chosen over `fetch` because only `XHR` reliably reports upload progress across browsers) and measures throughput from `upload.onprogress` events.
- **Ping/jitter:** several small round-trip requests to a no-cache Edge endpoint; average = ping, standard deviation = jitter. Packet loss is *estimated* from request timeout/failure rate — not true ICMP/UDP loss.
- **Network Strength is not a WiFi signal reading.** Browsers cannot access radio hardware (dBm) — this is a synthesized 0–100 score from your measured download, upload, latency, jitter and estimated loss, mapped to a plain-language label.
- **ISP/server panel** shows your public IP and ISP (via IP geolocation) and the Edge region that served your test — not literal ISP backbone routing data.
